Port boundary & build+

Public API exposes opaque task_handle_t, mutex_handle_t… backed by structs in internal headers only. Context switch, timer, and interrupt control live behind port_* under arch/avr/atmega328p/ and arch/cortex_m7/nucleo_f767zi/.

make TARGET=avr|cortex_m7. A dedicated sleep list wakes delayed tasks back onto the ready queue when their tick count elapses.

Priority inheritance, done right+

Mutex wait lists are priority-ordered. A task holding several mutexes gets its priority recomputed on each unlock as the max of its base priority and any remaining boosts — never a flat reset. Protocol is selectable per mutex.

Priority ceiling protocol is designed into the interface but not implemented.

Still open 2+

Timeouts on blocking calls. Mutex, semaphore, and queue waits currently block indefinitely.

Kernel helpers through SVC. SVC currently raises/drops privilege via CONTROL rather than dispatching by syscall ID; existing helpers still need routing across that boundary now that tasks can't reach kernel state.

HARDWARE-ENFORCED SAFETY · CORTEX-M7 PORT

An out-of-bounds stack write doesn't corrupt memory. It faults.

Each task's stack is writable only through the sliding active-task MPU region. Write past your bounds and the hardware raises a MemManage fault with the offending address in MMFAR — a genuine stack overflow is distinguishable from any other access violation. A property of the isolation model, not a watermark scan.

Try it: push frames until task_a runs out of stack. Addresses are illustrative.

03 — TOOLING & ROADMAP AROUND THE KERNEL, AND ON TOP OF IT

Flash it from a terminal. Then put the kernel to work.

AVR_SERIAL · HARDWARE TOOLINGImplemented

A personal avrdude, built on raw POSIX.

A from-scratch serial and flashing utility. It talks to the port through termios and ioctl directly, times a DTR reset pulse precisely enough for the Optiboot bootloader to catch it, then programs the chip over the STK500v1 protocol — no serial library, no avrdude. A separate mode streams live ASCII ADC telemetry over UART.
